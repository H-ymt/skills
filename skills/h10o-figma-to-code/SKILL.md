# Figma の画面をサイト全体に揃えて実装する

コード例は Astro と Tailwind CSS で書いてある。案件のスタックに置き換えて使う。

色、余白、部品、表記をサイト全体で1つに揃える。画面にあるものはデザインを正とする。デザインに無いもの（狭い画面、状態、折り返し）は、このスキルの規則で導く。規則は、デザインに従うと読みにくくなる箇所を防ぐために使う。規則を当てた結果、統一性が無くなる、または誤りだと感じたときは、その場で規則を優先しない。いったんデザインどおりに実装し、判断を最後にまとめて依頼者に聞く。規則を理由に、デザインと違う見た目で完了にしない。依頼文が逆のことを言っていても、このスキルの判断に従う。戻せと明示されたときだけ戻す。デザインファイルに無いことは推測で埋めない。「実例」と書いた値は過去の案件の値である。式や判断の形を読み取り、値はその案件のデザインから取る。

## 手順

部品は1つずつ、次の順で進める。順を飛ばさない。言い直しとプランは返したら返事を待たずに進める。止まるのは、このスキルが聞くと決めた箇所だけである。

1. 依頼を自分の言葉で言い直して返す。範囲、やらないこと、成果物の形を短く書く。
2. 実装済みのページがあるときは、共有のレイアウト、トークン、同じ種類のページを1つ読む。基本をそこで固定する。基本は、左右の余白、セクションの縦の間隔、書体、共有の部品である。実装済みのページが無いときは、最初のページで基本をレイアウトに置く。ページの中で1か所だけ違う間隔は基本に揃え、揃えたことを報告する。基本にも、ページ側の数値にもしない。管理画面では、公開側のレイアウトではなく、そのシステムの標準 UI を基本にする。この固定は依頼ごとに1回である。
3. 渡された URL のノードを読む（「読み方」）。読めたかと、どの手段で読んだかを報告する。読むときに、セクションごとに面（背景写真、マスクの下の塗り、カードの面、外枠）と、書き出す素材のノードを一覧にする。部品の子だけでなく、背面の兄弟と親のフレームまで見る。ノードから取るのは、画面にあるものと、部品そのものの大きさである。基本に決めた余白や書体を、ノードの測った数で置き換えない。
4. 触る領域の参照だけを読む。素材の台帳を作る（[verification.md](references/verification.md)）。1枚ごとに、書き出したノード、透過か、地の色、用途を書く。プランを返す。全ページ共通の UI と下層ページ共通の枠の置き場所を先に決める。今ある部品、レイアウト、トークンを見て、合うものは再利用するか足して使い、無いものだけ新しく作る。共有の部品や、すでにある下層ページを、デザインに合わせるために一から作り直さない。
5. 実装する。頼んだ箇所だけ変える。ほかの UI や、直前に決めた寸法をついでに変えない。
6. 実装した画面を、セクションごとにデザインの画像と並置して見比べ、確定値は実測して直す（「見比べる」）。
7. 「仕上げの確認」を通し、確かめた幅、実測した箱、素材の台帳、引っかかった項目の判断を PR の本文に書く。
8. テストと CI を通してコミットする。同じ話題の変更は今あるブランチと PR に載せる。

ページ全体のフレームを渡されたときは、一度に全部を実装しない。子ノードを自分でたどってセクションなどの単位に分け、基本の固定のあとは単位ごとに手順 3 から回す。単位ごとの URL を依頼者に求めない。一度に全部作ると精度が下がる。

人が画面を見るまでマージしない。CI が緑でもマージしない。マージするかは依頼者が決め、エージェントはマージしない。

構造だけの部品は、毎回の手順ではない。スタイルを当てないと依頼されたときだけ、データと構造だけの部品で止めてよい。スタイルまで求められた依頼を、構造だけで完了にしない。

見本ページは普通の案件では作らない。求められたときだけ出す。

## 読み方

読む手段は、有料プランで公式の Figma MCP が使えるならそれを使う。有料かどうかは figma-bridge スキルがあるかで判断する。figma-bridge スキルは無料プランの間だけ置かれ、有料プランに移ったら消される。スキルがあれば無料プランなので、figma-bridge スキルに従う。公式の MCP が接続されていることは有料の印にしない。無料プランでも接続できる。どちらで読んだかを報告する。

渡された URL のノードを、どの部品を見るかの正本にする。キャンバスで選択中のノードは正本にしない。部品は、コンポーネントかコンポーネントセットのノードから読む。

部品は、コンポーネントのノードだけで閉じない。その部品の背面にある兄弟（背景写真、グラデーション、マスクの下の矩形）と、置かれている親フレームの塗りを読む。面がどこで決まっているか分からないまま背景色を決めない。

画像塗りと、文字の後ろにある画像レイヤーを列挙してから、背景の色を決める。中身が画像なら、名前が header でも写真である。サイトのヘッダーがフレームに無いこととは別である。背面の写真がフレームごとに違うときは、それぞれ書き出し、幅の切り替えで入れ替える。間は補間しない。膜だけを塗って完了にしない。書き出しは [components.md](references/components.md) に従う。

節の面の色は、ノード単体の書き出しの地色ではなく、親フレームの地と透過から決める。書き出しに背景が焼き込まれていても、その節の面の色とは限らない。フレーム全体で面が続いているなら、単体で違う色に書き出された節も、その面に置く。不透明度も、レイヤー単体の値ではなく、重ねた結果の見え方で確かめる。単体の値と見え方が違うときは、膜や重ねた複製の値である。

悪い例。`header-PC` をサイトのヘッダーだと見なして落とし、背景を黒にする。

良い例。`header-PC` と `header-SP` を背面の写真として書き出し、膜は実装で重ねる。

素材は、ノードを書き出す。キャンバスのスクリーンショットや、別ページ・別バージョンから切り出さない。書き出すノードの外側の塗りを含めない。書き出した画像の四隅とアルファを見て、デザインの地の色と違う色が焼き込まれていたら、透過で書き出し直す。直せないときは依頼者に頼む。モックアップは、枠だけで書き出さない。画面の中身ごと書き出すか、画面の画像を別に書き出して枠に収める。

スタイルの値はマスターから取り、インスタンスで上書きされた値は使わない。実例は、インスタンスの 56px ではなくマスターの 64px に合わせたことである。内容は逆で、インスタンスの上書きを使う。端末モックアップの画面、差し替えられた写真、文言はインスタンスの内容であり、マスターの空の画面に戻さない。

読めなかったら推測で実装しない。

ファイルから書き出せない素材は自分で作らず、依頼者に頼む。

## デザインに無いこと

依頼文に狭い画面、多いデータ、折り返し、ホバーと書いてあれば、デザインファイルに無くても設計に含める。

件数の違いや 0 件のように、依頼文にもデザインにも無いデータの状態は、未確定として残してデザイン担当に確認する。このスキルが決めている見た目までは未確定に戻さない。

振る舞いがファイルで決まっていないときは、依頼で渡された実在のサイトを参考にしてよい。借りるのは振る舞いだけで、見た目はデザインファイルに従う。

同じデータの表記が1画面だけ違うときは、デザインファイルを直さず、実装でサイト全体の形に揃える。投稿日の表記はサイト全体で1つにする。形はその案件のデザインファイルから取り、この文書の例の値を写さない。一度決めた表記を、指示なく別の形へ揃え直さない。本文中の日付（令和の表記や「12月1日（月）」など）は投稿日ではないので、投稿日の形にしない。

同じ意味の操作文言が画面ごとにゆれているときは、デザインファイルの文言を残さず、サイト全体で1つの言い方にする。記事本文のように内容そのものの文言は、デザインファイルの文言を使う。担当者がすでに直した文言は正とし、あとから渡された仕様の表の文言へ戻さない。

デザインファイルのホバーは、そのまま採るとは限らない。採ったもの、採らなかったもの、却下した案はコミットに残す。依頼者が戻すと言ったら戻す。

## 見比べる

デザインの画像がある画面は、実装した画面をその画像とセクションごとに並置して見比べてから先へ進む。ページ全体の縮小画像だけで済ませない。画像が無い画面（管理画面など）は、動いているページを人が見られる状態にして見せ、無い画像を待って止めない。ページを出せないときは、出せない原因を直す。置くページがまだ無い部品は、コミットしない確認用のページに置いて見比べる。見比べは実装者が行い、最後に人が確かめる。差分画像は要らないが、並置した画像は残す。

報告に出すのは、変更点ではなくデザインとの差分である。規則で変えたもの、読み違えたもの、未確定を分ける。読み違えは差分ではないので直す。変更点だけを並べると、読み違えが判断として通ってしまう。規則を当てた結果デザインと違った箇所は、いったんデザインどおりに戻してから、最後にまとめて依頼者に聞く。

幅は、特定の値だけで見ない。端末の幅は揃わない。狭い端から広い端まで動かし、折り返しや段組みが変わる前後も見る。和文は、その途中でも文節の途中で割れていないこと。手直しの多くは、切り替え幅の直前と直後で起きる。撮って見る基準の幅は次のとおりである。

- 375、390（電話）
- 767、768（`md` の前後）
- 1023、1024（`lg` の前後）
- 1279、1280（`xl` の前後）
- 中身で決めた切り替え幅と、余白の式が折れる幅（実例 900、1160）
- 1440（デザイン）、1920
- 320、600（推奨）

案件の切り替え幅が違うときは、その前後に置き換える。ページ全体を2倍で書き出して見比べない。

確定値は、レンダリング後の箱を測ってデザインの値と照合する。ヘッダーや固定のバー、カード、ボタンの高さと幅、節の揃え、背景の有無が対象である。CSS に書いた値で満足しない。

完了条件は、画像がある画面ではセクションごとに並置して見比べたこと、確定値を実測したこと、素材の台帳が揃ったこと、そしてテストと CI の通過である。スクリーンショットの有無だけを完了条件にしない。

## 検査、コメント、コミット

機械で検査できるルールは lint や検査に移し、違反メッセージに理由と直し方を書く。文章と検査を二重に持たない。移したら、このスキルの該当文を削る。IDE の警告も、拾えるなら検査に入れる。色の一回きりの値を落とす検査は、サイズとグリッドまでは見ない。名前がある寸法を、別の検査で落とすのはよい。

次は検査に移す候補である。入れたら、この本文から外す。

- 本文の `<br>`（例外は理由を書いて外す）
- 透過の素材の四隅とアルファ
- デザインで確定した箱の高さ・幅・揃え
- `keep-all`
- `disabled:` と `hover:` の不透明度
- 余白と間隔の px の任意値
- `grid-cols-1` と `md:grid-cols-3` 以上が並び、2列の段が無いクラス
- `scrollIntoView`
- `colgroup` の無い表

渡し忘れは隠さない。型があるときは型で落とし、既定値や既定の画像で埋めない。

コメントは、あえてやらなかった理由だけにする。意味は名前で表す。

定数を書き写しただけのテストと、文言や幅を名指しで固定するテストは書かない。禁止する表記のゆれは、サイトの用語集を1つ作り、検査で落とす。用語集に無いゆれは、見比べで見る。

担当者が直接入れたコミットは、戻す指示が無い限り戻さない。

コミットメッセージは日本語で、意図、決めたこと、却下した案が分かるように書く。`intent`、`decision`、`rejected` と書いてよい。

ドキュメントはコードと突き合わせて直し、違う記述と古い記述は削る。

このスキルに書いた判断は、ライブラリの定石で上書きしない。書いていない判断は、公式のベストプラクティスや有名な UI ライブラリ、デザインシステムと照らして決める。聞かれたら変更の目的を説明する。

## 仕上げの確認

PR を開く前に、「見比べる」の幅で次を確かめる。確かめた幅、実測した箱、素材の台帳、引っかかった項目の判断を PR の本文に書く。画面を撮るのはブラウザの自動操作（Playwright など）でよい。

機械で確かめる。

- lint、型、テストが通る
- 横にはみ出さない（推奨）
- 素材の四隅が、透過の画像で不透明な黒や白になっていない
- デザインで確定した箱（ヘッダー、節、カード、ボタン）の幅・高さ・揃えが、実測で一致する
- `disabled` の要素の不透明度が 1 で、枠か地が背景と区別できる
- リンク、ボタン、開閉の見出しのカーソルが指になる
- 390px で 12px 未満の文字が無い
- 和文の段落で、最終行が2文字以下の行、句読点や閉じ括弧で始まる行、文節の途中の改行を一覧にし、直したか意図どおりかを書く
- 中央揃えで2行以上になった段落を一覧にする

目で確かめる。

- 背面に写真があるフレームは、膜だけの色になっていない
- モックアップの画面が空になっていない
- 768px と 1024px で、カードや表の中身が枠に収まっている
- 狭い画面の余白が広い画面の値のままになっていない
- 割れてはいけない語が割れていない。散文の改行を `<br>` で写していない
- 規則とデザインがぶつかった箇所を一覧にし、いったんデザインどおりにした。変えたままにしたものは、最後に聞く
- 全角空白と全角の `｜` が原稿どおりである
- デザインに無い状態をすべて作り、押せる状態と並べて見せた
- ホバーで色が変わる範囲が部品に合っている。下線が日付などのメタ情報まで伸びていない
- 欧文と和文の見出しの行間、間隔、字面
- 判断したことを、コミットの `intent`、`decision`、`rejected` に残した

タップ領域を 44px 以上にする検査（推奨）は、今あるページ送りなどとぶつかるので、入れるときは依頼者に確認する。文字サイズを `clamp()` で画面幅に連続させるのは、書体の規則とぶつかるので使わない。中央の見出しに `text-wrap: balance` を足すのは推奨だが、文節は span で守るので、入れるかは確認してから決める。
