# 公開画面の見た目

公開画面で色、書体、余白、画面幅、ホバーを触るときだけ読む。管理画面では読まない。

## 色

色は2層にする。プリミティブは生の色値を置く層、セマンティックはデザインファイルのセマンティック名を使う層である。セマンティックは必ずプリミティブを参照し、直値を残さない。部品はセマンティックだけを使う。すでにセマンティックとして使える色を、もう1段プリミティブで包まない。

名前は1つにする。同じ色の別名や、層を示す接頭辞を残さない。新しい名前は、今ある名前と意味がぶつからないか確かめてから決める。濃さの系列がある色は、その系列の中の名前にする。ホバー用の色もセマンティックトークンにする。

デザインファイルで変数になっていない色は、使う場所の名前で専用トークンにし、プリミティブを参照する。フッターのグラデーションをその場所の名前にしたのが実例である。

色の正本は1つのファイルに置く。共有する色は正本から生成し、二箇所に手で書かない。生成結果は変数参照を残し、実値をベタ書きしない。

段階色は 100 から 900 まで（必要なら 50 も）、プリミティブに直値で置く。プリミティブをほかの色を混ぜて作らない。混ぜるのは使う側だけである。段階を足したら、既存の値が変わっていないか確かめる。

スタイリングシステムの既定カラーパレットは消して、プロジェクトのトークンだけにする。消したことは検査で固定する。

## 書体

スタイリングシステムに既定の文字サイズスケールがあれば、そこにあるサイズはその名前を使い、無いサイズだけトークンを足す。独自のスケールを作らない。

文字サイズを指定しても、本文の行間を潰さない。和文本文の実例は行間 1.8、字間 0.04em である。

画面幅で文字サイズを変えるのは、大きい欧文の見出しだけである。その見出しはマスターのサイズに合わせ、狭い画面で調整する。

フォントの指定は部品ごとに書かず、ベースに置く。説明の文に飾りの書体や英字ラベルを足さない。書体の読み込み方は案件ごとに選び、方法を固定しない。

## 余白とサイズ

余白は、Figma の座標やレイヤー間の距離を写さない。測った数を `mt-[99px]` のような一回きりの値にしない。

間隔はスタイリングシステムの標準スケールを使う。ページ間で共通の縦の余白はレイアウト部品が持ち、ページ側では指定しない。広い画面の間隔を、それより狭い幅へそのまま使わない。幅が狭くなるほど詰める。1つの幅で半分にして、それより広ければ広い画面のまま、にはしない。スケールに無い間隔は、既存の段で足りるならその段にする。足りない段だけをスケールに足し、任意値では足したことにしない。

独自の余白トークンは、ページの左右余白のようにページ間で共通の式だけにする。

部品そのものの大きさは、マスターの値を使う。写真の枠やアイコンの寸法を、近い段へ自分で丸めない。

左右の余白は幅の帯で分ける。中間の幅では本文が細くならないよう、下限を画面幅の比率ではなく固定値にする。実例は、768px 以上で本文を最大 1080px にして中央に置き、左右の余白を残りの半分、下限を 40px にしたことである。1440px で左右 180px になる。下限を画面幅の 12.5% にすると、768px で本文が 576px まで細くなる。狭い画面で左右の余白が消えているときは、ゼロにせず比率で残す。縦に積み替えたら左右余白を詰める（実例 20px）。

部品の中の余白は、画面幅に連動させない。スケールの段で決め、`vw` や `clamp()` で伸び縮みさせない。値を変えるのは、横並びを縦に積む、列数を変えるといった配置の切り替えのときだけである。変える値は各幅のフレームから取り、フレームの間を補間しない。

置く場所で形が変わる部品は、画面幅ではなく親の幅で切り替える。

見た目の余白を詰めても、押せる範囲は 24px 以上を保つ。範囲を広げるときは見た目を変えない。

余白は表示した結果を見て1段ずつ詰める。閉じた開閉部品が本文の行間より広く見えるとき、テキストとアイコンの間隔が広いときも、見た目に合わせて詰める。

縦の揃えは箱の中央ではなく字面で合わせる。複数行のときは、アイコンや日付を1行目の中央に置く。形の重心で下に見える印は、文字の横に置くときだけ 1px 上げる。

部品は自分を親の幅いっぱいにしない。基本は中身の幅で、いっぱいにするかは置く側が決める。

写真の枠は、とても広い画面でもデザインの大きさで止める。

## 画面幅

切り替え幅は、フレーム幅ではなく中身が収まるかで決める。約 900px で6項目とロゴが1行に収まるため、より広い区切りを選んだのが実例である。グリッドの列数は画面幅で変える。

和文の左揃えと中央揃えは、幅で切り替えない。一度決めた揃えを、中間の幅だけ変えない。

中央揃えは、見出し、節のラベル、行の区切りが内容になっている短い声明だけにする。節の名前や、語を並べた標語がそれである。声明は中央のまま、文節の境目で改行する。包み方は [components.md](components.md) のマークアップに従う。

「です」「ます」で説明する文と、複数の文が続く段落は本文である。どの幅でも左揃えにする。広い画面でその塊がページの中央にあっても、文字は左揃えのままにする。行末に「す。」だけが残る文は本文である。中央のまま文節を包んで済ませない。

狭い画面、大量のページ、長い現在地、長いタイトルでも崩さない。長い現在地は行の中で折り返す。

狭い画面では背景を画面の端まで出してよい。文字の左端はページの余白に揃え、そのために余白を縮めない。

データの表は、狭い画面でカードにせず横にスクロールさせる。

## 狭い画面のフレームが無いとき

狭い画面での形が1つに決まらないものは、実装の前に聞く。ナビゲーションの畳み方、段組みの並べ替え、要素の表示と非表示がそれである。聞くときは、フレームの無い箇所を一覧にする。

それ以外は、このファイルの規則で導く。ページの左右余白は上の式、縦の余白は広い画面の半分、部品の中の余白は段を1つずつ詰める。横並びは中身が収まらなくなった幅で縦に積み、表は横にスクロールさせる。文字サイズは大きい欧文の見出しだけを変える。

導いた箇所は、完了の報告に「狭い画面のフレーム無し、規則で導いた」として列挙する。導いた値を、デザインファイルにあった値として報告しない。

## ホバーと動き

色の変化と開閉の長さはトークン1つで決める。基準は 250ms で、部品ごとに直書きしない。

ホバーは変わったと分かる差にする。部品全体の不透明度を下げない。押せるものにはホバーを付ける。ページ送りとテキストリンクにも色の変化を付ける。

一覧とカードのホバーは、下線ではなく色を変える。日付などのメタ情報も同じ色に変える。本文のテキストリンクは、下線と色の両方を変える。下線はラベルの範囲だけで、アイコンには付けず、二重にしない。ボタンには下線を付けない。ページ内アンカーの下線は、ホバーで色も変える。

開閉部品では、開いた状態とホバーで色を割らない。ホバーの面と押せる範囲は部品全体にする。開くときも閉じるときもなめらかに動かす。

ナビゲーションの現在地とホバーは同じ表現にする。実例は、濃い文字色と中央から伸びる 1px の下線である。

固定ヘッダーの下端は、ヘッダー範囲の外側でフェードさせる（実例 16px）。ヘッダーの範囲では不透明度とぼかしを変えず、裏の画像をロゴ越しに透かさない。

同じ種類のボタンはホバーも揃える。本文に出るファイルのボタンも、対応するボタンに合わせる。
