# 素材、面、実測の確認

手順 3 で面と素材を読み、手順 6 で比較するときに読む。文章で確認したことにしない。表と画像を残す。

## 面の一覧

セクションごとに、次を表にする。面がフレームの子でないときは、どの兄弟・親から取ったかを書く。

| セクション | 面 | 決まっている場所（ノード） | 実装 |
| --- | --- | --- | --- |
| 例：verify | カードの地 | マスクの下の矩形 `#d9d9d9` | `--surface-card` |

- 背景写真、グラデーション、マスクの下の矩形、カードの面、外枠を1行ずつ書く。
- 「地の色」で済ませない。写真と膜を分ける。
- 面が無いと判断したら、その根拠のノードを書く。

## 素材の台帳

画像1枚ごとに、次を残す。台帳に無い素材は使わない。

```json
{
  "path": "assets/images/verify/img-captured.webp",
  "sourceNode": "4029:12345",
  "transparent": true,
  "surface": "#d9d9d9",
  "width": 312,
  "width2x": 624,
  "use": "撮影されたことを示すカードの絵"
}
```

- `sourceNode` は渡された URL のページのノードにする。別ページ、別バージョン、実在サイトのスクリーンショットを書かない。
- `surface` は画像の下に置く色にする。透過でない画像は `transparent: false` とし、焼き込まれた地の色を書く。
- モックアップは、枠と画面を分ける。画面の素材も1行にする。

## 画像の検査

- 書き出すのはノードそのものにする。キャンバスのスクリーンショットや切り抜きにしない。
- 透過の画像は、四隅のアルファが 0 になっている。不透明な黒や白なら、地を焼き込んでいる。
- 四隅の色が `surface` と違うなら、透過で書き出し直す。直せないときは依頼者に頼む。
- 表示幅と2倍幅の2枚がある。`srcset` の幅と `sizes` が表示幅に合う。
- 画面の中身が空のモックアップを置かない。

## 実測

デザインで確定している箱を、レンダリング後に測る。CSS に書いた値ではなく、ブラウザが出した箱を測る。

| 箱 | デザイン | 実装 | 幅 |
| --- | --- | --- | --- |
| 例：ヘッダー | 60px | 60px | 1440 |

- ヘッダー、固定のバー、節、カード、ボタンを測る。
- 高さ、幅、左右の位置、揃え（中央か左か）、背景の有無を確かめる。
- 幅は「見比べる」の幅で測る。375、390、767、768、1023、1024、1279、1280、切り替え幅の前後、1440、1920。
- 差が出たら、丸めずにデザインの値へ戻す。

## セクション比較

- デザインのフレームをセクションごとに書き出し、同じ幅で実装のスクリーンショットを並置する。
- ページ全体の縮小画像だけで済ませない。
- 背景写真、カードの面、外枠、モックアップの画面、揃えを見る。
- 並置した画像は PR に残す。差分画像は要らない。

## 完了条件

PR の本文に次を書く。無い項目は未完了とする。

- 確かめた幅
- 面の一覧
- 素材の台帳
- 実測した箱とデザインの値
- セクション比較で直した箇所と、直さなかった箇所の理由
- テストと CI の結果
