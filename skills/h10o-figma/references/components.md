# 部品、画像、マークアップ

部品、アイコン、画像、マークアップ、スタイルの書き方を触るときだけ読む。

## 部品

同じ UI と同じ処理（投稿日の整形など）は、ページをまたいで1つにまとめる。既存の部品で足りるなら、新しく作らずそれを包む。

CMS が出す本文にも同じ見た目が当たるように設計する。本文リンクの印は呼び出し側で出してもよいが、出し方はサイト全体で1つにする。

置き場所は役割で分ける。見た目だけの部品、コンテンツの種類ごとの部品、CMS に依存する部品を混ぜない。見た目だけの部品が CMS の型やデータを import できないように検査する。

部品名をデータの種類に縛らない。依存しているのがパスだけなら、特定のコンテンツ名を入れない。

見た目のためだけの独自の指定は避ける。同じ指定の列を呼び出し側に毎回書かせず、部品の中に1回だけ書く。variant と呼び出し側の指定は部品の中で合成し、衝突したら呼び出し側が勝つ。合成の処理を別ファイルに出さない。

前後の移動のように対になる操作で片方が無いときは、空欄にせず灰色の押せない見た目で残す。押せない状態と現在地は見た目で示す。押せないボタンは `disabled` にする。リンクのように要素を残すときは `aria-disabled="true"` にする。現在地は `aria-current="page"` にする。独自の属性名は作らない。

## アイコンと画像

アイコンは管理と使い方を決めてから実装し、1つの部品に集める。一覧に無い形は、その部品に足す。その場の線で描かない。アイコンの色は親の文字色に従う。色ごとのバリアントは作らない。ボタンと本文のファイルのボタンで同じマークを使う。向きはデザインファイルと照らし、上下や回転を勝手に変えない。SVG には寸法を与え、箱だけを大きくしない。

ブランドのロゴは、デザインファイルの中の画像ではなく公式の配布素材を元にする。形式は中身を見て選ぶ。ベクターなら SVG にする。中身が画像のままのベクターはベクターとして扱わず、ラスター画像として WebP にする。

画像は使う場所のフォルダに置き、ファイル名は `img-` のあとに役割だけを書く（実例 `assets/images/page/img-hero.webp`）。2倍幅の画像は、同じ名前の末尾に `@2x` を付ける（`img-hero@2x.webp`）。中間の幅を足したときは、幅の数値を付ける（`img-hero-960.webp`）。外れたファイルは検査で落とす。

ラスター画像は、写真も透過のある画像も WebP にする。jpg や png の予備は置かない。アイコンとロゴは SVG にする。

ラスター画像は Figma から2倍で書き出し、表示幅と2倍幅の2枚を WebP で作る（60px 表示なら 60px と 120px）。品質は 80 程度にする。`srcset` には幅（`w`）で2枚を並べ、`sizes` は画面に出る幅どおりに書いて2倍にしない。2枚を基本にし、全幅の画像のように画面幅で表示幅が大きく変わるときは、中間の幅を足してよい。

写真の重ね効果（色の膜やグラデーション）は、写真を素のまま書き出し、実装側で重ねる。CMS から入る写真にも同じ効果が付き、色はトークンで変えられる。実装で再現しにくい複雑な効果だけは、書き出しに含めてよい。

favicon と OGP 画像は環境ごとの条件に合わせる。WebP の規則の外に置き、タッチアイコンは PNG、OGP 画像は JPEG か PNG にする。タッチアイコンは 180px の白背景にする。仮の favicon を残さない。ページが OGP 画像を渡さないときは、サイト共通の画像を出す。

## マークアップ

見出しの階層は見た目と分ける。h1 はそのページの記事タイトルにし、サイト名を h1 にしない。ラベルとして見える見出しは `p` にする。

開閉は `details` と `summary`、モーダルは `dialog` で作る。

デザインの見出しなどにある改行を、`<br>` で再現しない。`<br>` は、詩や住所のように改行そのものが内容の一部のときだけ使う。

和文は、どの幅でも文節の境目で改行する。広い画面で読めても、中間の幅で文の途中が割れるなら、その文で割れうる文節をまとめて包む。同じ行に並んでよい文節は `inline-block` にする。幅が足りないとき、その塊の前で改行する。デザイン上、どの幅でも独立した行にしたいまとまりは `block` にする。`block` のまとまりは、幅が決まっている親の中に置く。親を広げない。

実例は、中央揃えの説明で `"なりたい自分"` が `"なり` と `たい自分"` に割れることである。引用のまとまりを `inline-block` で包む。本文を中央揃えのまま包まない。本文か声明かは [visual.md](visual.md) の画面幅で決める。

手で包めない CMS 本文には、`word-break: auto-phrase` を足してよい。見出しとリードの包みの代わりにしない。`text-wrap: balance` は行の長さを揃えるだけで、文節の途中では割れる。折り返しの直しに使わない。

ページタイトルの区切りはサイト全体で1つにする。実例は全角の縦棒 `｜` である。

## スタイルの書き方

スタイリングシステムに登録されていない指定は、その検査があるときは落とす。検査から外す独自の名前は、プロジェクトの接頭辞で始める。

組版用のスタイルとぶつかる指定は、組版側に勝つ層へ移す。表のセルの余白や、文字が上に寄る問題はここで直す。

ベーススタイルは部品と同じ書き方に揃える。実行時にスクリプトで付けるクラスも、部品と同じ書き方で書く。素の CSS にはしない。
