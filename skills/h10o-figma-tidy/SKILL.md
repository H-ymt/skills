# Figma のレイヤーを、見た目を変えずに整理する

h10o-figma-to-code で実装する前の下ごしらえに使う。整理したフレームは、セクションの単位で実装に渡せる。

見た目を変えないことが最優先である。位置、大きさ、効果、クリップ、重なり順のどれかが変わる操作は、整理のためでもしない。

## どの MCP を使うか

有料プランで公式の Figma MCP が使えるなら、それを使う。有料かどうかは figma-bridge スキルがあるかで判断する。figma-bridge スキルは無料プランの間だけ置かれ、有料プランに移ったら消される。スキルがあれば無料プランなので、figma-bridge スキルに従う。公式の MCP が接続されていることは有料の印にしない。無料プランでも接続できる。

どちらを使ったかを最初の報告に書く。MCP ごとの手順は参照に分けてある。

- figma-bridge のときは [figma-bridge.md](references/figma-bridge.md)
- 公式の Figma MCP のときは [figma-mcp.md](references/figma-mcp.md)

## 手順

順を飛ばさない。言い直しを返したら、返事を待たずに進める。

1. 範囲を自分の言葉で言い直して返す。渡された URL のノードだけを対象にする。キャンバスで選択中のノードは対象にしない。URL の `node-id=9575-24656` は `9575:24656` として読む。
2. 対象のノードが読めるか確かめる。読めなければ、参照に書いた方法で依頼者に頼み、待つ。
3. 整理する前の画像を書き出して保存する。
4. 直下の子を一覧にする。名前、種類、y 座標の範囲、効果を見る。
5. y 座標の範囲でセクションに分ける。背景の長方形とコンテンツが直下にばらばらに置かれているときは、重なる範囲のものを同じセクションに入れる。もとから1つのノードでできているセクションは、グループで包まずに名前だけ変える。複数のセクションを中に持つフレームは、外に出すと位置が変わるので分けず、中の子に名前を付ける。
6. セクションの名前は、そのセクションの y の範囲の画像を見て、写っている中身で決める。元の名前や、ほかのセクションとの順番から推測しない。
7. 「整理の規則」に従って整理する。
8. 整理した後の画像を、前と同じ倍率と形式で書き出して見比べる。目で分かる違いがあれば、原因を特定して直してから先へ進む。目で区別できない書き出しの誤差は、場所を報告して進む。
9. 一時ファイルを消し、「報告」の形で返す。消せなかったときは、残ったパスを報告する。

対象が1セクションだけのときは、手順 5 と 6 のセクション分けを飛ばし、その中の部品（端末、カード、背景など）の単位で同じことをする。

## 整理の規則

- 中身のない入れ子をほどく。子が1つだけで、効果の無いグループのことである。不透明度、ぼかし、影などの効果を持つグループはほどかない。ほどくと効果が消える。探すのは、名前を付け直すのと同じ深さ（セクションとその1〜2階層目）までである。インスタンスの中はほどけないので対象にしない。
- 新しいまとまりはグループで作る。フレームにすると、位置やクリップが変わることがある。フレームにするのは依頼されたときだけである。
- 重なり順を元と同じにする。グループにすると並びがずれることがあるので、最後に直下の子の並びを決め直す。並びは、レイヤーパネルの上から下が、ページの上から下になるようにする（パネルの一番上が Header）。ただし、セクションどうしが重なる箇所では、手前に来る側を元と同じにすることを優先し、その組だけページの順と逆になってよい。
- グループの中の子の並びは、元の並びを保つ。
- 名前は英語で、役割が分かるものにする。例は `Header`、`Hero`、`Background`、`Content`、`Feature Cards` である。付け直すのはセクションと、その1〜2階層目までにする。それより奥の名前は触らない。テキストノードの名前は、文字の内容のままにする。同じ役割で並ぶもの（カードなど）は同じ名前にする。
- 役割を推測で決めた名前は、報告で推測だと書く。例は、URL 欄を隠しているように見える長方形に `URL Bar Mask` と付けたときである。
- インスタンスは名前だけ変える。元のコンポーネントには触らない。インスタンスの名前は中身で決める。中身が写真なら、`header-PC` という名前でも `Hero Background` にする。
- 削除しない。重複して見えるノードや、見えないノードは報告し、消すかは依頼者が決める。
- オートレイアウトは付けない。付けると位置が変わることがある。付けるのは依頼されたときだけである。
- 幅や位置の小さなずれ（幅 1442、x が -2 など）は直さず、報告する。
- バリアブルの登録や紐付けは、このスキルの範囲に入れない。頼まれたら、別の作業として扱う。

## 報告

次を短く返す。

- 使った MCP
- 整理後の構造のツリー。直下のセクションと、その中の主な要素の名前
- やったこと。ほどいた入れ子、まとめたもの、並べ直したもの
- 前後の画像を見比べて同じだったこと
- 触らなかったこと。奥の階層の名前、小さなずれ、重複に見えるノード
- 推測で付けた名前
- 元に戻すときは Figma のバージョン履歴から戻せること

作業中にページ名などが変わっていて、自分が変えたものでないときは、そのことも書く。
