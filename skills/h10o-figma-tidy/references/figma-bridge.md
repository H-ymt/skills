# figma-bridge で整理する

接続の確かめ方と書き込みの条件は figma-bridge スキルに従う。ここには、整理で引っかかることだけを書く。

## 読む

- 対象のノードは、プラグインで開いているページになければ選択できない。中身の一覧（`get_design_context`）も選択から取るので、取れない。`get_metadata` の `currentPage` が対象のページと違うときは、そのページを開いてフレームを選択するよう依頼者に頼む。
- `get_design_context` は選択中のノードを読む。`set_selection` で対象を選んでから、`depth: 1` で直下の子を取る。深くするのは必要な子だけにする。
- `get_node` と `get_screenshot` は、大きいフレームだと出力が長すぎて読めない。ページ全体には使わない。
- 子の中を少しだけ見たいときは、`get_layout_tree` の `maxNodes` を小さくする（4〜8 程度）。深さ優先で返るので、直下の子の一覧には使えない。
- 接続が切れたら（`No plugin connected`）、プラグインを開き直し、「WebSocket Connected」と出ているか確かめるよう依頼者に頼む。ページを切り替えると切れることがある。

## 画像

- `save_screenshots` で保存する。保存先は MCP サーバーの作業ディレクトリの中でないといけない。外を指すと失敗する。作業ディレクトリの中に一時フォルダ（例 `.figma-tmp/`）を作って保存し、終わったら消す。
- ページ全体は `scale: 0.25`、`format: "JPG"` で十分に見比べられる。
- 保存した画像は Read で見る。
- セクションの名前を決めるときは、そのセクションのノードを1つずつ `save_screenshots` で書き出して見る。縦に長いページ全体の縮小画像では、どの範囲に何があるかを取り違えやすい。

## 書く

- 入れ子をほどくのは `ungroup_node`。返ってきた子の ID で次の操作をする。
- まとめるのは `group_nodes`。子は同じ親の下にある必要がある。
- 名前は `set_node_properties` の `name`。同じ名前を付けるときは `nodeIds` でまとめて変えられる。
- 直下の並びは `reparent_nodes` で決め直す。同じ親を指定して、直下の子を下から上の順に渡す。渡した順に上へ積まれる。
- バリアブルを作る・紐付けるツールは無い。頼まれたら、figma-bridge ではできないと答える。
